# Automated test coverage

Current baseline: accepted stable/0.2.25 and its immutable paired v0.2.25 tester. The packaged suite has 449 distinct units. A complete run reports 28 stages: one unit stage, 26 functional stages and one final full security challenge on a newly created owned container. The measured current host produced 76 PASS and 0 FAIL; discovery-dependent check counts can vary on other hosts.

This is a behavioral inventory, not 100% line/branch coverage or a general security certification. Historical measurements are in [the coverage archive](docs/history/TEST_COVERAGE_0_2_25.md). Current receipts and platform limits are in [IMPLEMENTED.md](IMPLEMENTED.md).

## Test layers and how to run them

- Portable standard-library unit/failure tests are discovered from every `tests/test_*.py` module. The packaged tester supplies its exact shared code, test files and catalogs. Run these outside the checkout as shown in [DEVELOPMENT.md](docs/DEVELOPMENT.md#portable-and-packaged-units); source discovery has one intentional archive-only skip and is not the release's no-skip result.
- Native functional commands and real PTYs invoke the separately supplied product archive. Version and product SHA-256 are recorded. Temporary Projects and `test-<UUID>` targets isolate this run; stop-all tests do not affect user containers.
- Public installation/channel checks use actual downloaded artifacts, manifests, source origins and installed hashes. They supplement the portable suite and are not added to its unit count.
- Functional stages finish before the single complete challenge. GPU-off functional checks test device/runtime removal and unavailable CUDA; they do not rerun the complete challenge during each toggle. The independent host entry selects a user container, uses the same module and restores its original state.

## Current measured limits

- Current complete local/test/stable measurements use prepared Ubuntu 26.04 WSL, LXD client/server 6.9, NVIDIA and x86_64. The user supplied fresh SSHFS/LXD install/init success and manual terminal/About acceptance; those are separately identified user reports. Earlier Ubuntu 24.04 WSL fixture/socket-recreation evidence remains historical.
- Native Ubuntu/cloud, ARM64, native NVIDIA CDI, AMD/Intel GPUs and other storage backends have no new native validation. Unsupported GPU computation and optional Windows UNC checks are explicitly recorded when unavailable.
- Actual tmux 3.6 display-engine tests cover Unicode reflow and grow/restore/height-only resizing. Portable PTYs also cover controls, input and restoration. Extreme contraction can move old active rows into native scrollback; they remain historical. This does not certify every emulator/SSH client.
- Corrupt queries/registries, same-name replacement, PID/device-number reuse, operation timeout, publication failure and VM rejection include fault injection. They do not assert live disk exhaustion, destructive daemon/host failure or VM boot testing.
- AppArmor is disabled on the measured WSL kernel. UID/GID mappings, namespaces, seccomp and supported device/resource boundaries were tested; AppArmor confinement was not.
- Windows UNC filesystem operations have earlier native evidence where WSL interop was available. Explorer GUI, live ACL-bearing fixtures, offline VHDX mounting and universal metadata/WSL compatibility are not certified.
- CPU/memory/process UI controls, disk quotas, custom ports/traffic/login rules and post-terminal restart-entry are pending design, not current test coverage. See [pending decisions](REQUIREMENTS.md#pending-decisions).

The report group name `tui` is retained for compatibility and tests the inline menu. Test report `unit_tests` retains identifiers, modules, failures/errors/skips/expected failures/unexpected successes. Later stages not run after failure remain `not_run`; cleanup/report failures prevent overall success. Optimized Python (`-O` or `PYTHONOPTIMIZE`) is rejected.

## Documentation and handoff validation

The authorized documentation/handoff batch additionally checks Markdown paths/anchors, current-state consistency, historical preservation, portable project instructions, archive checksums, full Git history, offline restore, non-overwrite behavior and byte-identical rebuild of all three accepted zipapps. Its packaged-unit receipt and public archive verification are recorded after they pass; this batch does not add product tests or claim a new native full-suite run.
